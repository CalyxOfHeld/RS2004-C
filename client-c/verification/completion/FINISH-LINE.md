## Rules that keep this finite

1. Before a gate begins, list its scenarios and expected results in its evidence record. Add a scenario only when a concrete observed failure or an explicit source requirement affects that gate; record why. Do not create another open-ended audit because there is usage left.
2. A passing gate stays closed unless a later change or observed regression affects it. A fix gets targeted verification and relevant regressions; broad checks repeat only when the change warrants them.
3. Distinguish blockers from limits. Crashes, data loss, wrong supported actions, stuck ordinary workflows, broken persistence and missing declared source behavior are blockers. Exhaustive arbitrary cache/loop/input combinations, every scheduler interleaving, later revisions, other platforms and bit-identical audio hardware output are outside this release profile.
4. Existing reports retain their actual scope.71/71 incoming routes is source coverage, not a percentage of finished gameplay. Historical6,796 renderer screens and1,799 recovery frames are credited at their pinned binaries; they are not claimed as fresh reruns.
